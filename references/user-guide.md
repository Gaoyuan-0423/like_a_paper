## 这个 Skill 做什么

`like-a-paper` 不是“模仿几篇论文后直接生成全文”的工具，而是一套带人工审批闸门的循证论文写作流程。它先核对用户的确定性研究材料，再研究期刊语料、作者关联语料或二者的组合，形成可审批的写作合同；合同与段落蓝图获批后，才逐句生成英文、中文对译、证据映射和逻辑关系；最终只用获批句子组装干净稿件。

## 三种使用模式

### 1. 期刊模式 `journal`

适合以下目标：

- 已经确定投稿期刊；
- 希望学习该期刊相关论文的摘要、引言、方法、结果、讨论和结论写法；
- 不针对某一位作者。

### 2. 作者语料模式 `author`

适合以下目标：

- 希望研究某位成熟学者多篇论文中的论证方法；
- 论文分布在不同期刊；
- 重点学习问题组织、证据排序、主张强度和段落衔接；
- 不复制该作者的独特措辞或个人口吻。

系统会区分期刊、主题、共同作者、课题组、时间阶段和编辑加工的影响，输出的是“作者关联语料画像”，不是对作者本人的绝对归因。

### 3. 混合模式 `hybrid`

同时使用目标期刊语料和目标作者语料。二者先独立蒸馏，再合并。发生冲突时，科学证据和期刊硬性要求优先。

这是材料充足时的推荐模式。

## 如何安装

将仓库放入 Codex 的 Skills 目录，并确保技能目录名为 `like-a-paper`：

```bash
git clone https://github.com/siyunhao2025-beep/like_a_paper.git <CODEX_HOME>/skills/like-a-paper
```

```text
<CODEX_HOME>/skills/like-a-paper/
├── SKILL.md
├── README.md
├── assets/
├── agents/
├── references/
└── scripts/
```

如果环境没有单独设置 `CODEX_HOME`，通常使用用户目录下的 `.codex/skills/like-a-paper`。安装后重新加载技能列表或重新打开任务。

## 最简单的启动方式

在新任务中明确调用：

```text
使用 $like-a-paper，以期刊模式处理我的论文。
目标期刊：……
文章类型：……
稿件、LaTeX 或 PDF 路径：……
最终数据、图表、统计输出与代码路径：……
目标期刊强相关论文语料路径：……

论文中的样本、数据版本、处理方法、图表、数值结果和统计结论已经定稿。
请先审查并冻结科学证据，再检验语料充分性。
在 Gate 1 写作合同和 Gate 2 全文段落蓝图分别得到我明确批准前，不要写正文句子。
```

如果同时研究目标期刊和目标作者：

```text
使用 $like-a-paper，以混合模式处理我的论文。
目标期刊：……
目标作者：……
研究材料路径：……
期刊论文路径：……
作者跨期刊论文路径：……
匹配对照论文路径：……
请分别验证两个模型；没有通过的模型不得参与写作。在 Gate 1 与 Gate 2 分别得到批准前，不要写正文句子。
```

如果只研究一个作者：

```text
使用 $like-a-paper，以作者语料模式研究某作者跨期刊论文。请区分作者稳定习惯、期刊要求、共同作者影响和年代变化。不要模仿独特措辞。
```

## 建议准备的材料

### 必需或强烈建议

- 核心研究问题；
- 数据和版本说明；
- 方法、参数及代码位置；
- 最终或候选图表；
- 图表对应的数值和统计结果；
- 样本纳入、排除和质量控制规则；
- 已知限制；
- 当前论文或提纲；
- 参考文献库；
- 目标期刊及文章类型。

### 期刊语料

- 与研究问题高度相关的目标期刊论文；
- 目标期刊作者指南；
- 尽量包含完整摘要、引言、方法、结果、讨论和结论。

### 作者语料

- 目标作者主导的多篇论文；
- 尽量覆盖不同期刊、年份、主题和共同作者组合；
- 若有作者贡献声明，一并提供；
- 最好补充同期、同刊、相近主题但不包含目标作者的对照论文。

## 建立项目目录

Skill 可以运行：

```bash
python scripts/init_workspace.py D:/my-paper-work --mode hybrid
```

可选模式为 `journal`、`author` 或 `hybrid`。脚本会建立：

```text
00_intake/              研究材料与检查清单
01_corpus/journal/      目标期刊语料
01_corpus/author/       作者关联语料
01_corpus/controls/     对照论文
02_distillation/        文献蒸馏与充分性判定
03_contract/            写作合同与审批记录
04_blueprint/           段落蓝图
05_sentence_ledger/     逐句台账
06_manuscript/          干净论文
07_audit/               最终审计
```

不要把唯一一份原始数据直接交给脚本改写。项目目录应使用副本或明确的只读输入路径。

## 实际工作分为七步

### 第一步：确定性内容审查

Skill 会先检查：

- 数字是否互相一致；
- 图、表、图注和正文是否一致；
- 样本数量能否核对；
- 统计单位是否正确；
- 是否存在没有依据的因果结论；
- 是否有未解决的方法选择；
- 哪些内容可以视为冻结，哪些仍然是暂定。

如果关键矛盾可能改变结论，系统会停止并要求用户处理，而不是继续润色。

### 第二步：语料研究与蒸馏充分性闸门

Skill 不会把“用户上传了几篇论文”自动等同于“已经学会期刊或作者写法”。它会先把语料分成发现集和保留验证集，再检查候选规则能否在未参与规则生成的论文中复现。

期刊模型默认至少需要：

- 8篇可用的目标期刊全文；
- 其中至少5篇与当前主题、方法、尺度或科学任务直接相关；
- 当前期刊作者指南；
- 至少3个相互独立的作者团队；
- 至少2个发表时间段；
- 至少2篇保留验证论文；
- 每个要学习的论文部分至少4个可用样本；
- 反例检索和留出验证通过。

作者关联模型默认至少需要：

- 10篇目标作者关联全文；
- 其中至少6篇属于一作、通讯、共同一作/通讯、单作者或明确承担初稿写作；
- 至少2本期刊；
- 至少2种共同作者或课题组配置；
- 至少4篇来自2种以上情境的匹配对照论文；
- 至少60%的论文有可判断的作者角色或贡献信息；
- 至少2篇保留验证论文；
- 每个要学习的部分至少4个可用样本；
- 移除最大期刊/共同作者/课题组簇后，所谓“稳定特征”仍然成立。

系统只允许三种判定：

- `PASS`：可以进入写作合同，但仍不能直接写正文；
- `SECTION_LIMITED`：只能学习并撰写列出的合格部分；
- `FAIL`：不得声称已经完成可靠蒸馏。

混合模式必须让期刊模型和作者关联模型分别通过。一个模型合格不能掩盖另一个模型不合格。失败后可以补充文献、缩小范围、明确降级为单一合格模式，或者放弃“语料驱动风格”并改用普通循证写作；不能仅靠用户说“接受风险”就把失败改成通过。

#### 失败后的诊断标签与正确操作

诊断标签只说明下一条合法路线，不是第四种判定，也不会把 `FAIL` 改成 `PASS`：

- `JOURNAL_ONLY_ELIGIBLE`：期刊侧通过、作者侧失败。若用户明确批准，系统会丢弃全部作者规则，从期刊模式重新起草写作合同。
- `AUTHOR_ONLY_ELIGIBLE`：作者侧通过、期刊侧失败。若用户明确批准，只使用作者关联规则；期刊只保留已经核验的正式格式要求。
- `EXPLORATORY_AUTHOR_PROFILE_ONLY`：作者关联论文足以分析混杂，但不足以可靠归因。可以阅读报告，不能让画像约束生成句子。
- `FIELD_CONVENTION_PROFILE_ONLY`：目标期刊或作者样本不足，但跨期刊的直接相关文献足以总结本小众领域通常需要交代的证据和条件。它不能冒充目标期刊或作者风格。
- `FORMAL_REQUIREMENTS_ONLY`：只有当前投稿指南足够可靠。系统只执行篇幅、栏目、数据声明等明文规则，正文改用普通循证写作。

如果结果显示 `JOURNAL_ONLY_ELIGIBLE`，可以这样批准：

```text
我理解混合模式仍为 FAIL。批准切换为期刊模式；彻底丢弃失败的作者画像，重新起草期刊模式写作合同，并停在 Gate 1。
```

如果不想降级，可以这样继续补料：

```text
不批准降级。请列出作者模型唯一的主阻断项、尚未建立的后续检查，以及最少需要补充的文献类型；不要开始写作。
```

系统应先报告一个根本阻断项，再把因前置条件失败而无法执行的留出验证或移除最大簇测试标成 `NOT ESTABLISHED`，而不是伪装成多个相互独立的失败。

运行校验：

```bash
python scripts/validate_corpus_adequacy.py 02_distillation/corpus-adequacy.json --output 02_distillation/corpus-adequacy-verdict.json
```

### 第三步：形成写作合同

Skill 会输出：

- 实际读到的文献数量和筛选边界；
- 排除、重复、不可读或标签错误的文件；
- 期刊写作画像；
- 作者关联语料画像；
- 作者、期刊、主题、团队和年代的混杂分析；
- 各部分的写作方法；
- 主张强度和语气规则；
- 禁止模仿的表达；
- 拟采用的论文结构；
- 仍需用户决定的问题。

然后进入第一道人工闸门并停止。

建议用明确语言批准：

```text
批准 Gate 1 的写作合同，按当前规则建立全文段落蓝图。
```

如果只批准部分：

```text
只批准摘要和引言规则。讨论部分的因果语气需要进一步降低，修改后再次提交。
```

### 第四步：段落蓝图

Skill 会在写句子之前说明每一段：

- 要回答什么问题；
- 承担什么功能；
- 使用哪些本研究结果；
- 使用哪些外部文献；
- 与上一段、下一段如何衔接；
- 最多可以得出什么结论；
- 哪些结论不能写。

蓝图完成后进入第二道人工闸门。

批准示例：

```text
批准 Gate 2 的引言蓝图。先逐句写引言，不要开始其他部分。
```

### 第五步：逐句台账

每一部分开始前，智能体先用简短中文说明：这一部分要讲什么、在全文中承担什么功能、主要依赖哪些证据、怎样承接前后内容。随后，每个候选句子默认只向用户显示四项：

1. **English**：准备进入论文的英文句子；
2. **中文**：忠实对译，语气强度不能偷偷改变；
3. **对应依据**：文献句或忠实来源说明、本研究图表/统计结果、方法记录，或者段落逻辑；
4. **修改说明**：与原稿相比改了什么、为什么改；若为新增句，则说明它执行了哪条蓝图或写作合同规则。

这里有一个重要例外：不是每句话都应该硬配一条文献句。本研究结果应对应 Figure、Table 或冻结统计输出；方法句应对应方法、数据或代码记录；纯衔接句应说明它来自已批准的段落逻辑并且不需要外部引用。只有外部事实、前人结果和文献比较才显示短文献摘录或忠实释义、引用位置及支撑关系。

句子编号、主张类型、主张上限、前后句逻辑、风险标记和审批状态仍保存在内部机器台账中。用户默认不需要看这些字段；需要详细审计时，可以要求“显示审计视图”。

每一部分末尾只问：

```text
这一部分是否需要修改？如果不需要，请回复“无需修改，继续”。
```

回复“无需修改，继续”表示批准当前展示的准确版本。若需要修改，直接指出句子内容或位置即可，不必记内部编号。例如：

```text
第三句的“demonstrates”改成“suggests”，因为这篇文献只是类比支持；删除最后一句，它与上一句重复。其余句子不变。
```

智能体只重写受影响的句子；已经批准且不受逻辑影响的句子保持不动。最终目标不是让用户长期管理台账，而是逐部分确认后生成完整论文。

### 第六步：组装干净稿件

只有状态为 `approved` 的句子会进入论文。逐句证据、中文翻译、内部风险标记和审批信息不会出现在投稿稿件中，而是保留为独立审计文件。

### 第七步：反向审计

系统从最终稿逐句回查：

- 数字和单位；
- 图表与正文；
- 引用是否真正支持附近主张；
- 观察、解释与推测是否分开；
- 因果语言是否超出研究设计；
- 摘要和结论是否超出正文；
- 是否存在过度接近来源的连续措辞；
- 组稿时是否出现未经批准的改动。

## 逐句台账的验证与阅读

检查机器可读台账：

```bash
python scripts/validate_ledger.py 05_sentence_ledger/sentence_ledger.jsonl
```

生成便于审阅的 Markdown：

```bash
python scripts/render_ledger.py 05_sentence_ledger/sentence_ledger.jsonl --output 05_sentence_ledger/sentence_ledger.md
```

默认输出“英文—中文—对应依据—修改说明”四栏。需要查看内部 ID、主张上限、逻辑、风险和审批元数据时：

```bash
python scripts/render_ledger.py 05_sentence_ledger/sentence_ledger.jsonl --view audit --output 05_sentence_ledger/sentence_ledger-audit.md
```

检查与本地文献文本的连续词组重合：

```bash
python scripts/check_phrase_overlap.py --draft 06_manuscript/manuscript.txt --corpus-dir 01_corpus/text --n 8
```

重合检查只是提醒，不是抄袭判决。技术名词、仪器名和通用学术表达需要人工判断。

## 中断后如何继续

重新进入任务时，可这样要求：

```text
使用 $like-a-paper，读取项目目录中的 project.json、approval-record.md、写作合同、段落蓝图和逐句台账。先汇报当前审批状态，再从最后一个未批准句子继续，不要重写已批准内容。
```

如果数据或图表发生变化，要明确说明：

```text
Figure 4 和对应统计结果已更新。重新打开证据冻结，列出受影响的段落和已批准句子，在我批准前不要自动传播修改。
```

## 用户最终会得到什么

- 文献筛选和语料登记表；
- 期刊模型与作者关联模型的蒸馏充分性判定；
- 期刊/作者关联写作蒸馏报告；
- 经用户批准的写作合同；
- 段落逻辑蓝图；
- 中英双语逐句证据台账；
- 审批记录；
- 干净论文；
- 引文与证据映射；
- 最终一致性和原创性审计报告。

## 成本与适用范围

严格逐句模式的上下文和时间成本通常显著高于普通改稿。它适合：

- 重要投稿；
- 需要训练科研写作能力；
- 证据链复杂；
- 容易发生因果夸大或引用错配；
- 用户愿意逐部分审批。

它不适合用户只需要快速语言校对、格式修正或短摘要压缩的场景。此时应明确要求简化流程，而不是假装执行了完整蒸馏与逐句审计。
